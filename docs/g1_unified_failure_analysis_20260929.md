# walk1_g1.pkl：统一参考后的失败诊断

分析对象为已有的 `acc_data/lafan_unified_diagnosis_20260928.failure.npz`
和 `/tmp/g1_unified_diagnosis.log`。该运行使用当前统一参考启动配置，
额外记录 3、4、5 秒的 QP 快照，预算 12 秒，在 8.114 秒失败。
本次只分析记录和代码，没有改变控制器或重新调参。

## 结论

运动任务的参考已经统一，但运动参考、接触约束和切换条件仍不匹配。
该轮从未进入单支撑，不能继续用旧实验“第二步落地失败”解释它。

1. 4.526 秒进入 PREPARE_STEP，计划第 114 帧转为左脚支撑。
2. 5.000 秒停在源第 112.50024 帧，此后参考速度为零。
3. 等待期间仍命令双脚支撑。1794 个 PREPARE_STEP 样本中，单脚平衡
   检查通过次数为 0；80% 左脚承重检查曾通过 81 次，但联合条件从未通过。
4. 8.114 秒 QP 校验失败；此前已出现明显身体下沉与向前失稳。

最后一个有效控制历史样本的关节 RMSE 为 0.465 rad，根位置误差
0.462 m，根姿态误差 0.659 rad；没有覆盖原文件 7839 帧。

## 已证实的失配

### 全身参考与双支撑几何

在 112.50024 帧，参考右脚踝位置为
`[1.427256, 4.537414, 0.074393] m`；5 秒实际右脚踝约为
`[1.426312, 4.575355, 0.035045] m`。
参考与实际承重足位相差约 3.79 cm 水平位移和 3.93 cm 高度。
此时 feet_pose 的支撑脚行被屏蔽，双脚由接触约束维持在地面，
关节姿态却对应正在滚动抬跟的右脚。几何一致的全身目标仍可能违反接触约束。

按当前模型的四个脚底角点计算，源右脚最低/最高高度为
`-0.00741 / 0.06360 m`，左脚为 `-0.00818 / -0.00217 m`。
这反映参考滚动和毫米级地面误差，不能把它描述为整只右脚已经离地。
初始统一竖直对齐不能保证后续每个支撑姿态严格贴合地面。
上述角点是控制模型几何，不是完整 USD 碰撞网格的逐点穿透审计。

### 切换条件与停止姿态

`support_balance_ready` 要求捕获点位于下一支撑脚的局部
`x ∈ [-0.04, 0.11] m, |y| ≤ 0.02 m`，水平 COM 速度不超过 0.06 m/s。
5 秒时局部捕获点约为 `[0.1003, -0.0710] m`，侧向超出门控边界约 5.1 cm。
6 秒时速度已经很小，但局部侧向位置仍约为 -0.0703 m。
因此并非只差等待速度衰减；冻结的参考没有提供通过该门控所需的承重运动。

### 承重目标与承重门控

`managed_load_transfer` 的软接触力目标由参考 ZMP 分配。
5–7 秒时目标左脚占比约 71.4%，实测在 5–6 秒约 62.7–65.2%；
管理器首次确认要求至少 80%，且必须同时满足平衡检查。
这不证明物理上无法达到 80%，但表明当前生成的目标并未要求完成门控所需的转移。

## 已排查与尚未证明

- 全部 4057 个已执行控制步的关节、骨盆参考一致性误差为 0；
  逐步重算足端位置、COM 位置/速度/加速度的最大差也均为 0。
  旧的独立屈膝/COM 覆盖不是这轮的直接原因。
- 自碰撞事件记录为空，选取的参考样本没有关节位置越界。
  这不是整段运动通过所有限位和碰撞检查的证明。
- 7 秒 COM Y 加速度请求 +0.974 m/s²，QP 预测 -0.0909 m/s²，
  表明维持姿态与支撑约束时，恢复运动仍在任务折中中被牺牲。
- 最后一轮失败 QP 的大扭矩/摩擦残差属于被校验拒绝的候选，不能说成实际下发了那些扭矩。
- 尚未完成原文件全段逆动力学可行性审计，也未证明放开门控就能安全完成原始步幅。

## 建议的修复顺序

1. 在首步 100–129 帧审计接触点：区分平脚、滚动边接触和完全离地，
   将参考 q/v/a 与接触几何作为同一阶段计划验证。
2. 门控未就绪时，生成完整的承重/减速过渡，而不是一直停在第 112.5 帧。
   过渡需要同时满足支撑、关节和力矩限制，并最终达到门控要求。
3. 若沿用动态行走，采用包含后续落脚的可行性判断；不要把准静态门控
   简单放宽，也不要直接跳帧或强制释放尚在承重的脚。
4. 接触与参考一致后再比较 QP 任务优先级，并区分 QP 请求误差与实际执行误差。
